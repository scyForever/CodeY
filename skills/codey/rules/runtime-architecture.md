# Runtime architecture

CodeY has two explicit planes. The primary rule-governance plane scans repository-authored instructions as untrusted evidence, creates revision-bound Rule Patches, renders CodeY/Codex/Claude/Cursor adapter artifacts, and runs bounded trials in detached worktrees. Applying or rolling back a Rule Patch requires exact source/target hashes and explicit approval. The optional execution plane keeps the original `CodeYAgent`: `cli.py` builds `WorkspaceContext`, provider client, `SessionStore`, tools, skills, hooks, and the task-level `CognitiveLoop`. `ContextManager` gives reviewed repository rules their own audited budget section before task routing. Cognitive evolution patches and repository Rule Patches are separate schemas and stores; do not use task-level shadow metrics as evidence for external-agent rollout.
